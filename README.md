# 分支：feature_resume_layout

这个分支基于`featture_resume_sub_templates`，面向简历自动化排版对功能做一些封装和容器化喵~  

`ResumeTemplate.py` 是本分支的**中层**（对底层构件的调用与便捷封装），
`ResumeCore.py` 是**顶层**（面向使用者与开发人员的领域模型与流程编排）。

## 如何使用？

**期望两种使用方式，目前的完成度不同**：

| 使用方式 | 状态 |
| --- | --- |
| 开发者把这个库下载下来，在源文件里 `import` 并构造数据 | ✅ **已可用** |
| 源文件读取 `.md` 等文本文档，自动排版 | ⏳ 待做（**前置**：`.md` 格式规范未定，见 `SKILLS.md` I.1）|

### 五分钟上手

```bash
# 1. 拿到字体（必需，见下一节「资源获取」），放进 Resources/
# 2. 复制个人模板，填你自己的信息
copy demo_multi_version.py my_resumes.py     # Windows
#   cp demo_multi_version.py my_resumes.py   # Linux / macOS
# 3. 改 my_resumes.py 里 [填写] 标记的地方
# 4. 跑
py my_resumes.py
#   只生成某几个版本：
py my_resumes.py --only 后端开发岗
```

产物在 `./output_multi/{姓名}_{职位}_{公司}.pdf`。

> `my_resumes.py` **已被 `.gitignore` 排除**（含你的真实信息，永远不会被提交）。
> `demo_multi_version.py` 是**虚构数据**的完整示例，可以入库、也建议留着当参考。

### 我该改哪个文件？

| 你想做的事 | 改哪里 |
| --- | --- |
| 填/改简历内容、增删版本 | `my_resumes.py`（你的个人文件） |
| 调间距、边距、缩进、配色、字号 | 同上 —— `Spacing(...)` / `Theme(...)` 都能在调用侧表达 |
| 改**样式的全局默认值**（如姓名行字号） | `ResumeTemplate.py` 的 `STYLES` 字典 |
| 加/改子模板（新版面结构） | `ResumeTemplate.py` |
| 改排版引擎（几何、断行、行高） | `LayoutEngine.py` —— 属底层，改动要谨慎 |

**日常使用只需要动 `my_resumes.py`。** 完整可调项总表（留白 15 项 / 版式 34 项 /
内容字段 / 版本与批量）见 **`SKILLS.md` 的 H 节**；计划中的改动见 **I 节**。

### 四个概念（理解这四个，其余都是填值）

| 概念 | 是什么 |
| --- | --- |
| **内容** | 姓名、学校、项目、技能…（`Profiles` / `SkillsAwards` / `Details` / `Section`）|
| **留白** | 各处间距，单位 mm（中层 `Spacing`）|
| **版式** | 页面、边距、缩进、配色、样式（顶层 `Theme`）|
| **版本** | 一次投递 = 选哪些节 + 配哪档留白/版式（`ResumeVersion`）|

关键：`Section` 的 `title` 是**取用键**，`ResumeVersion.sections=[...]` 引用的就是它；
而 `sections` 的**顺序 = 呈现顺序**。所以投不同公司通常**只需加一个 `ResumeVersion`**，
不用复制任何内容。

```python
from ResumeCore import Profiles, Section, Details, ResumeBook, ResumeVersion, Theme
from ResumeTemplate import Spacing

book = ResumeBook(profile=me, skills_awards=sa, spacing=Spacing())
book.add_section(项目经历).add_section(教育背景)        # 素材入池
book.add_version(ResumeVersion(                        # 一个投递版本
    name="腾讯-后端", company="腾讯科技", job="后端开发工程师",
    sections=["项目经历", "教育背景"],                   # 顺序即呈现顺序
    spacing=Spacing.compact(),                         # 逐版本调留白
    theme=Theme(page_padding=12),                      # 逐版本调版式
    summary="…"))
book.render_all()                                      # 批量生成
```

## 资源获取

### 字体（**必需**）

`Resources/` 下的字体文件**不入库**（约 117 MB），需要自行下载。

> ⚠️ **缺字体会明确报错并中止**（不是静默降级）——
> `wrapped_height()` 会把 fpdf 的 CJK 异常包成可读的中文 `RuntimeError`。
> 这是**有意的**：静默产出"中文变空白"的 PDF 比明确报错危险得多。
> （本文档此前写"静默降级为空白、退出码 0"，**2026-10-13 实测为假**，
> 见 `SKILLS.md` G.4 / `TECHNICAL.md` 4.9。）

需要的是**霞鹜文楷（LXGW WenKai）**，作者 LXGW，采用 SIL Open Font License 1.1，可免费商用。

- 项目主页：<https://github.com/lxgw/LxgwWenKai>
- 发布页（选最新 Release）：<https://github.com/lxgw/LxgwWenKai/releases>
- 等宽版本（可选，`LXGWWenKaiMono*`）：<https://github.com/lxgw/LxgwWenKaiMono>

下载后按下列**文件名**放入 `Resources/`（代码按这些名字引用）：

| 文件名 | 用途 |
| --- | --- |
| `LXGWWenKai-Regular.ttf` | 正文（注册为 `LXGW` 的常规体） |
| `LXGWWenKai-Bold.ttf` | 粗体（注册为 `LXGW` 的 `B` 风格） |
| `LXGWWenKai-Light.ttf` | 可选 |
| `LXGWWenKaiMono-Regular.ttf` | 可选，等宽 |
| `LXGWWenKaiMono-Bold.ttf` | 可选，等宽 |
| `LXGWWenKaiMono-Light.ttf` | 可选，等宽 |

> 最少只需要 `Regular` 与 `Bold` 两个。若解压后的文件名与上表不同，请重命名。

### 图标与照片（可选）

顶层与中层引用了若干图标与照片，**这些资源尚未入库**。底层排版引擎不依赖它们。

```
icon.png  icon_Education_History.png  icon_Project_History.png
woman_student.png  photo_1.png
telephone.png  email.png  locate.png
social_media.png  contact_address.png  website.png
black_circle.png          # add_para 的默认圆点（顶层联系方式用）
```

**缺图片不会报错** —— `ImageObject` 静默跳过绘制，该位置留空，其余排版正常。
`Theme.validate()` 会把"缺哪些图标"作为**警告**报出来（不阻断渲染）。
排查「图标不见了」时先确认这些文件是否存在。

## 三层 API 速览

分层依赖只向下：`ResumeCore.py`（顶层）→ `ResumeTemplate.py`（中层）→ `LayoutEngine.py`（底层）。

### 顶层：数据容器 + 渲染器（`ResumeCore.py`）

| 类 / 函数 | 作用 |
| --- | --- |
| `Profiles` / `SkillsAwards` / `Details` / `Section` / `Resume` | **纯数据**，不 import 引擎、不做 I/O |
| `Theme` | 版式配置（页面、边距、缩进、配色、样式）|
| `ResumeVersion` / `ResumeBook` | 多版本管理（素材池 + 装配 + 批量渲染）|
| `ContentConfig` / `RenderConfig` | 整合入口的"内容 / 呈现"配置对 |
| `build_layout(resume, theme, spacing)` | 把数据落成排版树（唯一认识中层词汇的地方）|
| `render(resume, output_dir, *, spacing, theme, debug, creation_date, filename, pdf)` | **无副作用**渲染 |
| `render_many(...)` / `render_into(pdf, ...)` | 批量 / 一个 PDF 装多份 |

> ⚠️ **`render()` 不修改 `resume`** —— 旧版 `Generate()` 会往自己身上写
> `_root` / `_pdf_path`。同一容器可反复渲染、可批量。自检 **V1** 守着这条。

### 中层：子模板（`ResumeTemplate.py`）

**15 个子模板**，一律以**方法**形式挂在任意节点上调用，返回**结果句柄**：

| 方法 | 返回句柄 | 主要部件 |
| --- | --- | --- |
| `add_split` / `add_basic` | `SplitHandle` | `node` / `left` / `right` |
| `add_info` | `ProfileHandle` | `icon` / `text` / `split` / `icon_range` / `text_range` |
| `add_photo` | `PhotoHandle` | `photo` |
| `add_section_heading` | `TitleHandle` | `icon` / `text` / `divider` |
| `add_detail` | `DetailsHandle` | `key` / `during_time` / `tags` / `description` / `brief` |
| `add_detail_head` / `add_detail_body` | `DetailHeadHandle` / `DetailBodyHandle` | 可单独使用的两个半成品 |
| `add_highlight` | `HighlightHandle` | 重点突出行 |
| `add_bullets` / `add_bullet_list` | `BulletHandle` / `BulletListHandle` | 单条 / 批量分条目 |
| `add_para` | `ParaHandle` / `ParaDeferredHandle` | **图标段落**（圆点 + 文本，行高由内容决定）|
| `add_section` | `SectionHandle` | 组合模板：节标题 + 该节全部详情 |
| `add_text_row` | `TextObject` | 一行文本（技能/证书/荣誉共用）|
| `add_spacer` | `LayoutObject` | 流式留白 |

**6 个旧名已退役**（会 `AttributeError`，不留兼容层）：
`add_profile` / `add_profile_photo` / `add_section_title` / `add_details` /
`add_summary` / `add_details_list`。

句柄都带 `fill(...)` / `apply(data)`（就地填充，返回 self 以便链式），
`apply` 同时接受 dict 与 dataclass。

**留白集中在中层的 `Spacing`**（15 项，frozen dataclass）——
`Spacing()` / `.compact()` / `.loose()` / `.scaled(k)` / 单项微调。

#### **批次 7：文本落点与盒内对齐（两处缺陷，详见 TECHNICAL.md 3.4d）**

**一、传给 `pdf.cell` 的格子高漏了单位换算（主因）**

`render()` 用 `pdf.cell(_w, own_h, txt)` 画字，其中
`own_h = 字号 × line_height_ratio`。但 fpdf 的 `cell(w, h)` 的 `w/h` 是
**用户空间单位（mm）**，而字号是 **pt** —— pt 当 mm 用，格子高虚高 **2.8346 倍**。
fpdf 又把文字**垂直居中**在格子里，于是基线落到格子中央：

```
22pt 的文字 -> own_h = 26.4（当 mm）-> 基线相对盒顶下移 15.53mm
而节标题的盒子只有 14.5mm 高        -> 文字基线直接跑到盒外
```

修法：`pdf.cell(_w, own_h * PT_TO_MM, txt)`，新增常量 `PT_TO_MM = 25.4 / 72.0`。

> 注意区分：`py = cy + line_top + (line_h - own_h)` **不需要换算** ——
> `line_top` / `line_h` 与 `own_h` 同为 pt 数值，相减得到的行内偏移自洽。

**二、`align_y` 从未被渲染读取**

`_place()` 用 `align_y` 决定"盒子摆在哪"，`render()` 却完全不读它，
文字一律贴内容区顶边 —— `VCENTER` / `BOTTOM` 对文字落点毫无作用。
修法：在 `render()` 里按同一条对齐规则分配盒内剩余空间。

**三、标定与验收**

受控实验（固定格子高 10mm，取 8/12/16/24/32/40pt）拟合得：

```
基线偏移 = 0.10584 × 字号 + 4.99968        截距恰为 h/2
```

证明 fpdf 按 mm 正确解释了格子高，问题只在调用方传错了单位。据此得到落点公式：

```
文字基线 = 盒顶 + padding.top + dy_align
           + (字号 × line_height_ratio × PT_TO_MM) / 2 + 0.10583 × 字号
  其中 dy_align = VCENTER → (盒内高 − 文字实高)/2
                  BOTTOM  →  盒内高 − 文字实高
                  TOP / NONE / FLOW → 0
```

实测影响面：节标题、姓名行等 22pt 文本的基线相对盒顶 **15.53mm**，
**超出 14.5mm 高的盒子**；9 个文本块合计 **45.82mm** 的纵向虚位移。

**四、自检入口新增第 13 节断言**

这个缺陷能长期存活，正是因为引擎自检里没有"文字必须落在盒内"的断言。
新增的第 13 节直接观测"文字画到哪"（包住 `pdf.set_xy` 记录落点）：

- 三种对齐（`TOP` / `VCENTER` / `BOTTOM`）的落点必须两两不同 —— 旧实现下三者相同；
- 落点顺序必须是 `TOP < VCENTER < BOTTOM`；
- 相邻间距必须等于 `(盒内高 − 文字实高)/2`（实测 12.46mm，与公式一致）；
- 落点偏移必须落在盒内、且不超过合理上界。

**五、升级须知**

所有载体的**文字位置都会变**。任何"为了抓住偏低文字"而调过的盒高，
都需要按上面的公式重新校一遍。中层（`ResumeTemplate.py`）的参数表见
功能分支文档的「中层调参手册」。

#### **12：05 修复左栏内容右溢出（`add_profile` 横带宽度）**

**症状（实测确认）**：左栏所有个人信息行的文本右边界到 `87.43mm`，
而左栏内容区只到 `64.29mm` —— **溢出 23.14mm**；右栏无越界。

**根因**：`add_profile` 把"左缩进 `row_inset`"做成了
"整条横带右移 3mm + 手动收窄宽度"。但 `create_band` 会按**父内容区宽**
重算自己的宽度与各格位置，与手动定的值打架 —— 横带仍按住户外框宽 `54.29`
铺开，两格按 1:1 分，文本格起点被推到 `40.14`。

**修法**：缩进改为**行容器的内边距**（`content.padding = Padding(left=3)`），
让 `create_band` 一开始就拿到已经收窄的内容宽 `51.29`。横带 `x` 回到 0，
`create_band` 的比例计算自然给出正确的格子宽度与位置。

修复后与旧版（split 容器带 `Padding.left(3)`）的几何**逐项一致**：

| 节点 | 修复前 | 修复后 | 旧版 |
| --- | --- | --- | --- |
| `..._split` | `x=13.00 w=54.29` | `x=13.00 w=51.29` | 宽 51.29 |
| `..._icon_range` | `x=13.00 w=4.00` | `x=13.00 w=4.00` | `x=13` |
| `..._text_range` | `x=40.14 w=47.29` | `x=17.00 w=47.29` | `x=17` |

越界元素数：左栏 `15 → 0`，右栏 `0 → 0`。

> 教训：`create_band` 的格子位置由**它自己的宽度**决定，任何"建完之后再挪"
> 的补偿都会被下一次 `_measure` 覆盖掉。缩进要在**建带之前**通过父的内边距表达。

#### **13：10 查出"字整体偏下"的根因：引擎两处文本渲染缺陷**

**症状（用户实测反馈）**：所有文字相对应在的位置整体偏下。

**排查过程**（两次自我否定，都记下来以免以后再走弯路）：

1. 先怀疑"盒子比文字高 → 文字从顶部画 → 视觉偏低"。**实测否定**：
   全部文本节点的盒内空白量都是**负的**（文字实高 > 盒内高），
   这个机制根本没被触发；
2. 再怀疑"渲染器不读 `align_y`"。确实是缺陷，但**不是"偏下"的主因**：
   实测证明盒高从未超过文字，对齐方式无从生效；
3. **真正的主因**：`pdf.cell(_w, own_h)` 的 `own_h = 字号 × 1.2` 是 **pt 数值**，
   而 fpdf 的 `cell(w, h)` 的 `h` 是**用户空间单位（mm）**。pt 当 mm 用，
   格子高虚高 **2.8346 倍**；而 fpdf 把文字**垂直居中**在格子里 ——
   22pt 的文字被放进 **26.4mm** 高的格子，基线相对盒顶下移 **15.53mm**，
   而节标题的盒子只有 14.5mm 高 —— **文字基线直接跑到盒外**。

**验证方式**（全部可复现）：

- 受控实验：固定格子高 10mm、六个字号（8/12/16/24/32/40pt），
  拟合出 `基线偏移 = 0.10584 × 字号 + 4.99968` —— 截距恰为 `h/2`，
  证明 fpdf 按 mm 正确解释了格子高；
- 修复方向对照：22pt 文字放进 14.5mm 盒子，现状基线 15.53mm（越界）、
  换算后 6.99mm（盒内）；
- 用引擎自身的测量接口核算全部 9 个文本块：
  **4 个原本越出盒底，修复后全部回到盒内，合计消除 45.82mm 纵向虚位移**。

**两处缺陷与修法**（属 `master`，已实装验证后**在本分支还原**）：

| # | 缺陷 | 修法 |
| --- | --- | --- |
| 1 | `pdf.cell` 的格子高漏换算单位（pt 当 mm） | `own_h * PT_TO_MM`，新增常量 `PT_TO_MM = 25.4/72.0` |
| 2 | `align_y` 从未被渲染读取（只用于摆放盒子） | `render()` 里按 `align_y` 加盒内偏移 `dy_align` |

> ⚠️ 落地到 `master` 时**所有产物的文字位置都会变**，必须重建基线；
> 且**功能分支的参数是针对旧行为调过的**，需要按 TECHNICAL.md **11.4b**
> 的落点表重新校一遍。

**产物**：诊断用的对照 PDF 收在 `_chk/`

#### **16：40 断行禁则 + 标点悬挂（引擎能力，待回 master）**

**问题**：引擎的断行是自写贪心装行，**没有任何中文排版禁则** —— 实测收尾标点会落到行首：

```
宽 60mm: '…还有括号（像这样'     宽 90mm: '…逗号、句号'
         '）以及书名号《示例》。'  <==       '。还有括号…'   <==
```

**顺带更正一处过期文档**：`measure_text` 的 docstring 声称"复用 fpdf2 的
`multi_cell`、必须显式传 `align='L'` / `wrapmode`" —— 那是批次 5 之前的实现，
现在不再调用 `multi_cell`，那两个 workaround 早已无意义。已改写。

**实现方式**：在"摊平成断行单元"这一层把违规的相邻单元**合并**成不可分单元，
而不是在装行循环里回溯。这样 `measure_text` 与 `render` 共用同一份 `lines`，
"量出的行数"与"画出的行数"必然一致。

```python
BreakPolicy(no_line_start=…, no_line_end=…, pair_brackets=True,
            hang_punctuation=True, hang_ratio=1.5)
BreakPolicy.loose()     # 退回旧行为
```

- **行首禁则**：`，。、；：？！）】》」』”’` 等 40 个字符不得落在行首
- **行尾禁则**：`（【《「『〔｛〖〘〚“‘([{<` 不得留在行尾
- **成对符号整体粘住**：只做禁则不够 —— 实测「（」会被留在行尾、「）」被挤到下一行，
  两者都违规，必须让成对符号整体不断开

**中途发现的副作用与解法**：禁则会制造**"只含标点的孤行"** ——
满行时「能。」被整体推到下一行，末行只剩「。」，**行数从 4 增到 5**。
解法是**标点悬挂**：尾部标点允许略微出界（上限 = 字号 × 1.5），
而不是被挤下去。这是中文排版的通行做法。

**实测效果**（16 个「文本 × 宽度」组合）：

| 指标 | 结果 |
| --- | --- |
| 断行发生变化的组合 | **9 / 16** |
| 行首/行尾违规 | **0**（旧行为下每段都有 1 处） |
| 悬挂带来的行数变化 | **只减不增**：文本3 在宽 40/60/80 下 6→5、5→4、4→3 行 |
| 非末行剩余空白 | **0.03mm**（关闭悬挂时 5.33mm）—— 悬挂让行填得更满 |

**⚠️ 对当前简历产物的影响：零。** 实测右栏描述可用宽 123.71mm，
现有 4 段文案**每段都没折行**，所以在该宽度下旧版本来就没有违规。
这次是**预防性修正**：换更长的文案、或更窄的栏目，就会立刻生效。
**因此不需要重建几何基线。**

**改动落点**：`LayoutEngine.py`（`BreakPolicy` + `_apply_break_policy` +
`measure_text(policy=…)` + `TextObject(break_policy=…)`），
中层 `add_detail` / `add_detail_body` 已透传该参数。
自检新增第 14 节五条断言（禁则零违规、loose 能复现违规证明有区分度、
成对符号不断开、悬挂只减行数、填满度）。

#### **19：40 四项连做：探针污染 → 内联嵌套 → 对齐可配 → 分条目批量**

按"先修缺陷、再加能力"的顺序一次做完。

**① 修探针污染产物**（你目视发现的"时间字段坏了"）

探针树原先直接 `render` 到简历 PDF 本身，往第 1 页顶部画了三段文字的**复制品**

同时把被一并注释掉的第 10 节基线断言恢复启用。

**② 修内联标记的嵌套缺陷**

`parse_inline_markdown` 原是**单层非递归**：命中 `<c:…>…</c>` 后内部整段当纯文本。
于是 `<c:CC0000>**都是重点**</c>` 会**字面输出 `**都是重点**`** ——
不报错、不丢弃，只是把 `**` 印在 PDF 上。而"粗体 + 彩色"正是给重点做强调最自然的写法。

| 写法 | 修复前 | 修复后 |
| --- | --- | --- |
| `<c:CC0000>**重点**</c>` | 字面的 `**重点**` | `B` + `#CC0000` |
| `**<c:CC0000>重点</c>**` | 字面的 `<c:…>` | 同上（两种顺序结果一致） |
| `**<c:CC0000>*三层*</c>**` | 错 | `B` + `I` + `#CC0000` |

> 实现要点：递归时必须传**外层未加本标记的 `base`**，否则内层片段会提前继承
> 本标记样式、再叠加一次就重复（症状：外壳内的普通文字也被染色）。

已知限制：`**粗*斜***` 仍有歧义，**改用 `<b>粗<i>斜</i></b>`**（实测可靠）。

**③ 对齐与行距变成可配置**

此前 `Style` 里**根本没有对齐字段**，中层各模板又把 `align_y` 硬编码 ——
这就是"时间怎么调都不动"的直接原因（不是引擎不会，是没口子）。


并补 `Style.replace()` —— 此前 `Style` 没有 copy/replace，就地改会污染共用的 `STYLES`。

#### **23：30 顶层重建（阶段一）：ResumeCore 改为纯数据容器 + 无副作用渲染器**

**决定**：顶层只做内容封装，渲染单开一层；`Resume` 是纯数据容器，
未来要用 Python 批量填写简历，**同一个容器会被复用多次**。删掉 `Lead`，改用中层 `Spacing`。
**顶层去适应中层**，不动中层 API。

**先揪出一个引擎级 bug**（`a5d19a0`）：`TextObject._source_h` 把 `measure_text` 的
**pt** 总高**直接当 mm** 返回 → 所有 `SizeY.CONTENT` 文本块高度放大约 **2.83 倍**。

判别性证据（同函数内单位不一致）：内边距 0→10mm 只让高度增 **20.000**（纯 mm），
而 padding=0 时高度是 **24.000** = 2 行 × 12pt 的 **pt 数值**。

**这解释了历史遗留** —— 旧顶层为什么需要 `description_height=50` 那种手调旋钮。
也因此**不需要给中层开工单**：技能正文的硬编码高度由现成的
`add_detail_body(height=None)` 承担即可（此前被这个 bug 压着不能用）。

**新结构**（单文件内按"认识什么"分四段）：
数据模型（纯数据，不认识 PDF）→ `Theme`（版式配置）→ `build_layout()`
→ `render()` / `render_many()` / `render_into()`（只读数据）。

**核心变更**：`Generate()` 方法 → `render()` 函数且**零写回**
（旧版会往 `Resume` 上写 `_root` / `_pdf_path` 等 4 个属性）。

**验收自检 V1–V10**（`py ResumeCore.py`），其中 **V1 是核心**：
`vars(resume)` 渲染前后必须完全一致。**反向验证过**：注入"渲染写回 `resume._root`"
的旧式缺陷 → 自检 exit=1；还原 → exit=0。

**过程中修掉两个自身缺陷**（都是"静默失效"型，靠自检才暴露）：
`creation_date` 按字符串设计而 fpdf 要 `datetime`（`except: pass` 吞掉了 `TypeError`）；
`render_into` 没为每份简历 `add_page()`（两份只出 1 页）。
